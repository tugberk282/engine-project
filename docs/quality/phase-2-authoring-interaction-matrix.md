# Phase 2 authoring interaction matrix

Issue: TUG-83  
Owner: Tuval (Editor UI/UX)  
Baseline: 2026-08-03, current dirty working tree

## Purpose and qualification rules

This is the release contract for the Phase 2 gate: a keyboard or pointer user can construct the canonical scene through the packaged editor; every mutation is undoable and persists; asset references survive move and restart. It records observable behavior, not the presence of similarly named classes.

Status vocabulary:

- `specified`: acceptance is defined but no qualifying rendered evidence exists.
- `source-contract`: a source/unit assertion exists; it is useful regression evidence but not observable parity.
- `rendered-partial`: a bounded desktop run exercises part, but not all, of the row.
- `rendered-pass`: a fresh packaged-app run covers every listed input, state, persistence/undo, and negative-path obligation with retained output.
- `blocked`: a named dependency prevents execution.

A row may become `rendered-pass` only when retained evidence identifies the source revision and dirty state, packaged artifact hash, Windows version, display scale, viewport size, fixture revision, exact actions, expected/actual results, and screenshots or event log. Keyboard claims require keyboard-only execution. Resize/DPI claims require each listed geometry. Assistive claims require an accessibility-tree capture or named screen-reader smoke. Source-pattern tests never qualify a row beyond `source-contract`.

## Canonical fixture and environments

Use a copy of `samples/vertical-slice` containing nested root/child/grandchild objects, two same-type components, editable scalar/vector/boolean/enum/string/reference fields, a prefab instance, a texture/material/model/script, a missing asset reference, and at least 1,000 Console entries across severities. Preserve the fixture input and resulting scene/project documents.

Minimum rendered matrix: Windows at 100%, 150%, and 200% display scale; editor at 1280x720, 1920x1080, and a resized 900x600 minimum; mouse and keyboard-only passes. Repeat persistence rows after editor restart. Perform drag rows with both valid and invalid targets. At 200%, verify the canvas remains sharp, hit targets align, menus remain on screen, and no essential control is clipped.

## Prioritized implementation issues derived from the matrix

1. **P0 — Transaction safety:** CH-03–06, IN-02–06, PR-04–08, SH-06, and TX-02–04. Acceptance: every mutation is exactly one undo unit; cancel/failure is byte- and model-non-mutating; save/restart preserves stable IDs/GUIDs and documented selection.
2. **P0 — Complete keyboard and focus path:** CH-01–07, SV-01–06, IN-01–07, PR-01–08, CO-01–04, SH-01–10. Acceptance: construct the canonical scene without a pointer; visible deterministic focus; dialogs/menus trap and return focus; shortcuts do not fire while editing text.
3. **P1 — Cross-panel selection/reference contract:** CH-01, SV-01, IN-01/03, PR-02/05/08, TX-01/04. Acceptance: one stable identity drives all views; asset moves and restart preserve GUID references; missing items remain recoverable.
4. **P1 — Layout, resize and DPI qualification:** SH-02–05 and SH-09. Acceptance: all minimum environments pass with aligned pointer hits, sharp canvas, keyboard resizing, clamped persisted bounds and no essential clipping.
5. **P1 — State and diagnostics completeness:** CH-07, IN-01/07, PR-01–07, CO-01–04, SH-08, TX-03. Acceptance: empty/loading/error/disabled/missing states are distinct, accessible, recoverable and non-destructive.
6. **P2 — High-volume and assistive-technology evidence:** CO-04 and all `F` obligations. Acceptance: published responsiveness budget at 1k/10k logs, accessibility-tree capture, and a named screen-reader smoke for the keyboard-only critical path.
